# Localization

## Supported languages

| Code | Language  | Native name |
| ---- | --------- | ----------- |
| `en` | English   | English     |
| `uk` | Ukrainian | Українська  |

English is the default. Codes are ISO 639-1 (`uk` is Ukrainian; `ua` is a country code and is rejected).

## Resolution order (implemented)

`resolveLanguage()` in `src/localization/resolve.ts`:

1. Explicit runtime override: `git2jira report --language uk`, `/jira-report --language uk`
2. Repository configuration: `<repo>/.git2jira.json` → `report.language`
3. Global configuration: `~/.config/git2jira/config.json` → `report.language`
4. Default: `en`

An unsupported override is a usage error (exit code 2). It never falls back silently, so a typo cannot
produce a report in an unexpected language.

```sh
git2jira config get report.language
git2jira config set report.language uk
git2jira config set report.language en --repo
git2jira config unset report.language --repo
```

The setup wizard (`git2jira init`, Phase 5) asks for the preferred language and stores it globally.

## What gets localized (Phase 3)

- **Free-text fields** of the structured report (`summary`, change descriptions, testing notes, risks,
  follow-ups) are written by the model directly in the target language.
- **Section headings** come from `ReportLabels` (`src/localization/catalog.ts`). Headings are not
  generated by the model.
- **Structure** stays language-independent: enums such as `kind: "added"`, the schema, and the comment
  footer are identical across languages.

Never translated: file paths, issue keys, branch names, identifiers (classes, functions, variables),
API endpoints, HTTP methods, commit SHAs, and code.

## Adding a language

1. Add the code to `SUPPORTED_LANGUAGES` and `LANGUAGE_NAMES`.
2. Add a `ReportLabels` entry (Phase 3 catalog).
3. Add model guidance for that language (Phase 3).
4. Extend tests.
